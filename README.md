# TerraGuard AI

TerraGuard AI is a prototype for reviewing possible land-cover and building changes between two dated images. It combines a React dashboard, a FastAPI service, a SQLite database, map overlays, and a saved LEVIR-CD+ pixel classifier. Results are **potential change candidates** for human review; the software does not establish ownership or prove illegal encroachment.

## What is implemented

- Authenticated dashboard, monitoring-zone and parcel views, alert review, user management, notifications, and CSV/PDF exports.
- Leaflet map overlays for zone, parcel, restricted-boundary, and alert GeoJSON, using CARTO Dark Matter basemap tiles.
- Local image upload and comparison, plus a local demo imagery provider. A Copernicus catalogue-search adapter is optional, but downloading scenes is not implemented.
- A pluggable change-detection job pipeline with an RGB VARI/brightness heuristic and a Pillow edge-difference placeholder.
- A trained LEVIR-CD+ HistGradientBoosting pixel classifier that returns a thresholded mask, red overlay, and pixel-change metrics.
- Explainable rule-based risk scores and an alert review workflow.

Seed imagery and the sample evidence image are synthetic illustrations generated by `backend/app/seed.py`, not real satellite or field photographs. The generated records and regions are demonstration data.

## Architecture

```text
React + TypeScript (Vite, port 5173)
        │ JSON/multipart, bearer JWT
        ▼
FastAPI (port 8001) ─────── SQLite via SQLAlchemy
        │                           │
        ├── analysis services       ├── users, zones, scenes, jobs
        ├── LEVIR-CD+ classifier    ├── changes, alerts, notes, evidence
        ├── risk/spatial helpers    └── notifications, audit logs
        └── /storage static files

Map tiles: remote CARTO Dark Matter / OpenStreetMap attribution
```

### Technology

- **Frontend:** React 18, TypeScript, Vite, React Router, Tailwind CSS, React Leaflet/Leaflet, Recharts, Lucide.
- **Backend:** Python, FastAPI, Pydantic v2, SQLAlchemy, PyJWT, bcrypt, NumPy, Pillow, Shapely, scikit-learn, Joblib, ReportLab.
- **Database:** SQLite by default. `docker-compose.yml` contains an optional PostGIS container, but the application is not configured to use it by default.

## Requirements and setup (Windows)

Install Python 3.10 or newer and Node.js 18 or newer. From PowerShell in the repository root:

```powershell
Copy-Item .env.example backend/.env

python -m venv backend/venv
backend/venv/Scripts/python.exe -m pip install -r backend/requirements.txt

# Put a fresh local signing key in the ignored backend/.env without printing it.
$secret = python -c "import secrets; print(secrets.token_urlsafe(48))"
$envFile = Get-Content backend/.env -Raw
$envFile.Replace('REPLACE_WITH_A_RANDOM_SECRET', $secret) | Set-Content backend/.env -NoNewline
Remove-Variable secret, envFile

Set-Location frontend
npm ci
Set-Location ..
```

`backend/.env` is local-only and ignored by Git. It configures SQLite, storage paths, demo mode, and optional Copernicus settings. Set a strong `SECRET_KEY` in production; the backend rejects a missing or placeholder key when `ENVIRONMENT` is `production`.

Start the backend and frontend in separate PowerShell windows from the repository root:

```powershell
.\run_backend.bat
```

```powershell
.\run_frontend.bat
```

The backend launcher seeds an empty database and starts FastAPI on `http://localhost:8001`. Vite starts on `http://localhost:5173` and proxies `/api` and `/storage` to port 8001. Open the frontend at `http://localhost:5173`; FastAPI interactive docs are at `http://localhost:8001/docs`, and health is `http://localhost:8001/api/health`.

The optional PostGIS service in Compose is not used by the default app. If starting it, provide `POSTGRES_PASSWORD` in the shell/environment first; Compose has no committed password.

## Demo login

When the database is empty, startup creates demonstration users for the administrator, monitoring officer, and field inspector roles. Use the role buttons on the login page to populate the demonstration login form. These seeded accounts and their credentials are for local demonstration only; replace or remove them before deployment. The demonstration zones, alerts, and imagery are synthetic sample data.

## API overview

All API routes are under `/api`; most require `Authorization: Bearer <token>`.

| Router prefix | Main routes |
|---|---|
| `/api/auth` | `POST /login`, `GET /me` |
| `/api/dashboard` | `GET /stats`, `GET /trends` |
| `/api/zones` | `GET /`, `GET /{zone_id}`, `POST /`, `GET /parcels/all`, `GET /boundaries/all` |
| `/api/imagery` | `GET /`, `GET /{scene_id}`, `POST /upload`, `GET /provider/search` |
| `/api/analysis` | `POST /run`, `GET /jobs`, `GET /jobs/{job_id}`, `GET /changes`, `POST /levir/predict`, `POST /levir/predict-upload` |
| `/api/alerts` | list/detail, status update, assignment, notes, evidence upload |
| `/api/notifications` | list, mark one read, mark all read |
| `/api/reports` | summary, CSV export, PDF export |
| `/api/users` | list/create users, list active users, toggle account status |
| `/api/settings` | get/update settings, admin audit-log query |

`POST /api/analysis/levir/predict` accepts JSON with `earlier_scene_id`, `later_scene_id`, and optional `threshold` (0–1). The upload alternative accepts multipart `earlier_file`, `later_file`, and optional `threshold`, `zone_id`, and `generate_alert`. Successful predictions return model metadata, dimensions, changed-pixel counts and percentage, and `/storage/masks/...` URLs for the mask and overlay. The output is explicitly labelled potential building change and requires human verification.

## LEVIR-CD+ model

The serving artifact is `backend/models/levir_change_model.joblib` (about 18 KB). It contains a scikit-learn `HistGradientBoostingClassifier`, feature-schema identifier, selected threshold, and training configuration. Inference is implemented in `backend/app/services/levir_service.py` and `backend/ml/levir_model.py`.

For every aligned RGB pixel, `extract_features()` builds 10 features: earlier RGB (3), later RGB (3), absolute RGB difference (3), and a 3×3 local mean difference (1). `predict_probability()` computes class-1 probability per pixel. The service thresholds probabilities (artifact/default threshold 0.7), saves a binary mask, and creates a red-tinted overlay on the later image. Images must decode as RGB and have matching dimensions.

The checked-in artifact metadata records 637 official training pairs split into 573 fit and 64 validation pairs, and 348 official test pairs. Training samples up to 64 positive and 64 negative pixels per fit pair after half-resolution resizing. Validation chooses a probability threshold by F1 over candidates 0.2–0.8. The training/evaluation code computes precision, recall, F1, and IoU against an RGB-difference baseline. **No final numeric test-metric report is included in this repository, so no accuracy score is claimed here.** The official dataset is not included in Git; the regular model integration test uses temporary synthetic images and does not need the dataset.

Limitations: this is a pixel classifier rather than a semantic building-segmentation network; it does not register/orthorectify images or interpret legal boundaries; it expects equal-sized inputs; and inference is dense over the full image. The model signals possible visual change only.

## Database and demo data

SQLAlchemy models are in `backend/app/models.py`. They cover users, zones, parcels, restricted boundaries, satellite scenes, detection jobs, detected changes, temporal observations, alerts, alert notes/evidence, notifications, audit logs, and system settings. Startup creates missing tables and seeds only when no user exists. The default database is `backend/terraguard.db`, which is ignored by Git. GeoJSON is stored in JSON columns and spatial calculations use Shapely helpers rather than a PostGIS database.

## Tests and production build

From the repository root:

```powershell
backend/venv/Scripts/python.exe -m pytest -p no:cacheprovider
Set-Location frontend
npm run build
```

The backend tests cover health/auth, spatial and risk helpers, dashboard/alert/report endpoints, and an authenticated LEVIR upload-to-artifact integration flow. The integration test creates its own temporary image pair. The frontend build runs TypeScript checking and Vite production bundling.

## Known limitations and deployment notes

- `DeepLearningSegmentationStrategy` is a Pillow edge-filter heuristic, not a trained U-Net. The spectral strategy uses RGB VARI and brightness differences, not multispectral NDVI/NDBI.
- Copernicus search is conditional and only queries catalogue metadata. `download_or_prepare_scene()` is a stub; the default local provider returns static demo entries.
- Settings GET values are hard-coded, and the update endpoint logs an audit event but does not persist settings.
- Temporal trend helpers exist, but the pipeline does not robustly match a candidate to the same spatial feature across separate runs.
- The comparison library uses a generated demo mask unless a saved alert mask is selected. The map background is a third-party street-map tileset, not satellite imagery.
- Review authorization and data-access scoping need production hardening. Prediction by filesystem path, upload size/content validation, broad CORS, localStorage token storage, and export download authentication should be reviewed before deployment.
- The Compose PostGIS service is optional and is not connected to the default SQLite configuration.

## Repository hygiene

Local `.env` files, databases, virtual environments, Node dependencies, datasets, caches, and `backend/storage/` runtime outputs are ignored. The demo seed code regenerates the sample storage assets for a fresh database. No screenshots are currently included.
